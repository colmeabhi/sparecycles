\section{Testing Results}
\label{sec:testing}

Table~\ref{tab:tests} lists our sixteen test cases. They cover normal operation (TC-01, TC-15), each failure the system is designed to survive (TC-02 to TC-04, TC-06, TC-12, TC-13), the security mechanisms (TC-05, TC-06, TC-16), the behavior of individual algorithms (TC-09, TC-10, TC-14) and performance (TC-07, TC-08, TC-11). The three main failure scenarios each run with one command (\texttt{make fail-volunteer}, \texttt{fail-faulty} and \texttt{fail-leader}) that starts a local cluster, injects the fault and checks the outcome, and most cases also have an automated Go test. Most automated tests run complete jobs inside one process over an in-memory gRPC connection, and tests that depend on time use short deadlines or a fake clock rather than relying on lucky timing.

The tests also found a real defect. The first run of TC-03 failed: the faulty volunteer had joined last, so it always received the third copy of each unit, and the two honest copies had already been accepted when its result arrived. Its five wrong results were turned away without ever being compared, so a faulty volunteer that always finished last would never have been detected. This led to the late-copy check of Section~\ref{sec:algorithms}, after which the same scenario caught every wrong result. The repeated runs on the final code also confirmed how the mechanisms combine: in TC-04, with a 20-second lease, gossip declared the volunteers' old identifiers dead and the new leader released their leases 4.5\,s after taking over, before any lease expired.

Continuous integration runs on every push to the main branch and on every pull request. It checks formatting with \texttt{gofmt}, runs \texttt{go vet}, runs all automated tests with the race detector (\texttt{go test -race ./...}) and builds every binary; separate jobs validate the Terraform configuration and build the Docker image. A change is merged only when all of these pass. The main limitation of our testing is its environment: all cases ran on a single machine, so network delay and loss between zones were not exercised, and the measurements should be repeated on the AWS deployment.
